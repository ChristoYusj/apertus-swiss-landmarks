# AI use in this project (disclosure)

| What | Tool / model | Role | Human oversight |
|---|---|---|---|
| Models under evaluation | `swiss-ai/Apertus-v1.5-70B` and `-8B` (CSCS hackathon endpoint) | Answer every test question | — |
| Comparison model | `google/gemma-4-31B-it`, open weights, via Hugging Face Inference Providers | Answers every test question in the same request format, as a reference point | Registered before the run for the core items and multiple choice (`docs/extensions_plan.md`); the second wording was also run on it (logged deviation) |
| Answer grading | `openai/gpt-oss-120b`, open weights, via Hugging Face Inference Providers (frozen prompt `judge-v1`) | Independent LLM judge on every free answer; its labels are final (multiple choice is graded by code only; 4 empty Gemma verdicts keep the code label). Apertus never grades itself | Code grader on 100 % as a second rater. Blind human audit of 522 Apertus-70B core answers (the pre-registered 20 % sample minus screened-out landmarks) by one annotator: judge vs human κ = 0.76. No human audit of 8B, Gemma, the extension items, `photo_alt` or `trap_lowinfo` |
| Judge dev set | Labels proposed by Claude (AI coding assistant) | 40 items to tune the judge prompt before it was frozen | The team lead ruled on the 4 hard cases and accepted the other 36 without item-by-item review |
| Judge-vs-code disagreements | Independent Claude agents | Re-read every core-item disagreement of the Apertus models against the written rules (two reads where the judge looked wrong); used only for a sensitivity analysis. Second-wording and Gemma disagreements were not re-read | AI-assisted, not a human audit; results in `disagreement_adjudication.jsonl` |
| Code-grader reviews | Claude agents | Read the code grader's labels and proposed rule fixes (reviews 2–5) | Each change is logged in `CHANGELOG.md` with its effect and pinned by regression tests; AI-assisted, not a human audit |
| Photo screening | Claude Opus 5.5 (8 screeners, 3 independent re-checkers) and a second AI agent (Hermes) | Privacy (people, plates, private interiors, personal text), wrong object, second view, too-generic photos | The team lead set the policy ("if unsure, exclude") and decided 6 edge-case photos on 4 landmarks. No person reviewed every shipped photo |
| AI cross-check of the audit sample | Second AI agent (Hermes) | Graded 526 of the 546 sampled answers (left the rest unscored as uncertain) | Reported as AI-vs-judge agreement (`ai_crosscheck_audit`), never as a human audit |
| Question templates | Drafted with an AI coding assistant (Claude Code) | Fixed sentences per language (FR, DE, IT, RM): `q-v1` (core), `q-v2-mc` and `q-v2-w2` (extensions) | `q-v1`: FR reviewed by French-speaking team members, DE/IT checked by back-translation. Extension templates: locked before the run without a recorded review. RM not reviewed by a native speaker, so RM results are labelled exploratory |
| Software | Written with an AI coding assistant (Claude Code) | Data pipeline, graders, harness, tests | Every step has automated regression tests; `make run` re-runs the code grader on every stored 70B answer and checks the final-label rule and the scores. The team reviewed the design decisions |
| Answer translation for annotators | `openai/gpt-oss-120b` (same judge endpoint), labelled as machine translation | English gloss of non-FR answers in the audit forms | The original answer is shown next to the gloss |

The answer keys come from Wikidata (CC0) and the official BFS municipality register. No AI system wrote a gold answer;
the rule-based cleaning of the keys (rules in code) is logged in `CHANGELOG.md`.
